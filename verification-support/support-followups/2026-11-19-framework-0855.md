## Cause And Change

Ordinary chat constructed its effective capability profile from the optional
retrieval allowlist alone. With no allowlist, its effective namespace set was
empty. The READ planner then intersected registered sources with that empty set
and advertised no indexed sources, although actual routing recognized the
deployment's registered namespace. The live model initially confused a plugin ID
with a namespace; its bounded repair could not use the hidden catalogue reliably.

OrchestrationPolicyResolutionStep now supplies its server-owned entity registry
to the default capability resolver. The resolver intersects registration with
configured restrictions; missing optional narrowing is no longer empty discovery.
The action-only overload remains appropriate for callers without a source registry.

Preserved controls:

- A required but absent allowlist remains empty.
- Disabled retrieval, absent/empty registration and unregistered allowlist names
  do not create a usable source.
- Explicit task/execution profiles, including an empty ceiling, are not expanded.
- Actual source selection is still an LLM decision; search authorization, tenant
  filters, budgets, write permissions and confirmation are unchanged.
- No hardcoded namespace, search-all recovery, text matcher, canned answer,
  additional model call or empty-history grounding exception was introduced.

No Support configuration workaround, document rewrite, migration, reindex or UI
change is part of this correction. Preserve all ten saved configuration sections,
original app/consumer identities and unrelated bindings through adoption.
