## 1) Purpose

Phase 2 makes Starter sellable.

The goal is to turn the read-only Shopify Companion product into a launch-ready paid package that a merchant can understand, install, configure, test, and buy without platform-operator explanation.

Canonical Starter claim:

- **Starter is full read-only embedded store intelligence.**

Starter should feel mature from day one because it is the first serious paid product.

---

## 2) Phase Boundary

Phase 2 owns:

- Starter entitlement truth
- Starter surface completeness
- merchant setup and launch readiness
- Knowledge Sync health language
- basic analytics and value reporting
- App Store assets and claim-safe copy
- support docs and launch runbooks
- design-partner rehearsal package

Phase 2 does not own:

- Elite governed actions
- order lookup
- return/exchange initiation
- support ticket creation
- discount or coupon application
- broad partner recruitment
- public partner signup
- WooCommerce
- generic product-factory expansion

Tier rule:

- Free is AI search only.
- Starter is all read-only embedded intelligence.
- Elite is Starter plus verified governed actions only.

## 3) Starter Product Truth

### 3.1 Included In Starter

Starter includes:

- product insight block
- AI search
- product FAQ
- comparison
- policy strip
- contextual pill
- read-only Companion chat/depth layer
- unlimited products
- products, pages, policies, collections, and approved content sources
- basic analytics
- optional `Powered by Loom Companion` badge
- custom accent color
- email support posture

### 3.2 Not Included In Starter

Starter does not include:

- order lookup
- add-to-cart
- cart update
- return/exchange initiation
- support ticket creation
- discount application
- governed write actions
- Deep Resolver claims
- broad autonomous support claims

### 3.3 Required Copy Rule

Starter copy should lead with:

- make every product page smarter
- AI product intelligence for Shopify
- embedded store intelligence
- read-only product, search, FAQ, comparison, and policy help

Starter copy should not lead with:

- AI chatbot
- autonomous sales agent
- AI employee
- full AI enablement layer
- action-taking support automation

## 4) Workstreams

### 4.1 Entitlements And Billing Truth

Deliverables:

- `Free / Starter / Elite` plan names everywhere active
- old `Growth / Pro` terminology removed or marked historical
- Free gated to AI search only
- Starter unlocks the full read-only surface set
- Starter unlimited-product posture
- Starter sync posture aligned with pricing docs
- optional powered-by badge for Starter
- custom accent color for Starter
- plan-aware UI copy and upgrade states

Acceptance checks:

- billing contract, storefront gates, merchant admin, App Store copy, and support docs agree
- direct storefront calls cannot access Starter-only surfaces on Free
- Starter store cannot access Elite write/action surfaces
- historical tier names are not used in current launch material

### 4.2 Read-Only Surface Completeness

Deliverables:

- product insight block launch-ready
- AI search launch-ready
- product FAQ launch-ready
- comparison launch-ready
- policy strip launch-ready
- contextual pill launch-ready
- read-only depth layer launch-ready
- shared loading, empty, setup-blocked, and error states
- mobile and desktop presentation polish

Surface quality bar:

- each surface must be useful on its own
- every answer must be grounded in store knowledge where possible
- weak data should produce honest fallback copy
- surfaces should avoid technical or operator language
- follow-up actions should route to the read-only depth layer unless the store is Elite and the action is verified

Acceptance checks:

- a product page can show insight, FAQ, policy, and contextual pill without visual conflict
- AI search produces useful results for natural-language queries
- comparison explains differences and shopper fit
- product FAQ answers from product, policy, review, page, article, and structured source evidence when available
- all Starter surfaces work without write scopes

### 4.3 Knowledge And Source Readiness

Deliverables:

- merchant-facing `Knowledge Sync` status
- source readiness for products, collections, policies, pages, articles/blogs, reviews, metafields, and metaobjects where supported
- clear freshness language
- setup blockers and next actions
- safe retry or support-handoff posture where sync is unhealthy

Language rule:

- merchant UI says `Knowledge Sync`.
- partner/operator surfaces may show vectorization, queues, providers, retries, and diagnostics.

Acceptance checks:

- merchant can see whether store knowledge is ready
- merchant can understand what source is missing
- surface quality degrades honestly when a source is absent
- raw platform internals stay out of merchant admin

### 4.4 Merchant Setup And Activation

Deliverables:

- install and onboarding path
- theme activation guidance
- surface placement checklist
- live preview or verification flow
- plan ladder with current plan and available surfaces
- launch readiness checklist
- merchant-safe support handoff

Activation checklist:

- app installed
- theme app embed active
- AI search placed or enabled
- product insight placed
- product FAQ placed
- comparison available
- policy strip placed near buying decisions
- contextual pill enabled
- Knowledge Sync healthy
- Starter plan active
- App Store/demo screenshots reflect live surfaces

Acceptance checks:

- a merchant can activate Starter without reading engineering docs
- blocked setup states show one clear next action
- readiness checklist matches actual entitlement and storefront state
- launch packet can be generated from current live posture

### 4.5 Basic Analytics And Value Evidence

Deliverables:

- query volume
- top shopper questions
- surface usage
- unanswered questions
- action-intent questions
- shopper journey by surface where available
- Starter-to-Elite demand signals without selling unavailable actions as live

Starter analytics should answer:

- are shoppers using the surfaces
- what are shoppers asking
- which surfaces create engagement
- what knowledge gaps should the merchant fix
- what action requests indicate future Elite demand

Acceptance checks:

- analytics are readable by a merchant
- action-intent reporting does not imply Starter can take action
- usage data distinguishes surfaces rather than showing only raw totals
- analytics can support the first review/design-partner conversations

### 4.6 App Store Package

Deliverables:

- final App Store listing copy
- product-page screenshots
- AI search screenshots
- product FAQ screenshots
- comparison screenshots
- policy strip/contextual pill screenshots
- short demo clips
- App Review guide
- screencast script
- launch dossier export
- design-partner checklist

Copy order:

1. smart product pages
2. AI search
3. product FAQ
4. product comparison
5. contextual policies
6. contextual pill
7. Companion chat/depth layer

Acceptance checks:

- listing copy matches the live surface set
- screenshots show real embedded intelligence, not only a chat window
- Free is described as AI search only
- Starter is described as full read-only store intelligence
- Elite claims are bounded or omitted unless verified

### 4.7 Support And Launch Operations

Deliverables:

- support runbook aligned to current product
- merchant help docs
- install recovery notes
- common blocker handling
- App Review response notes
- design-partner feedback capture template
- launch readiness export

Support scope:

- Starter support should help merchants install, place, sync, verify, and understand read-only surfaces.
- Starter support should not promise order support, returns, support ticket automation, or governed actions.

Acceptance checks:

- support docs use the same tier truth as the product
- support can explain Free vs Starter vs Elite without interpreting old docs
- launch/review packet does not expose operator-only internals to merchants

### 4.8 Verification And Release Discipline

Required checks:

- Free, Starter, and Elite entitlement boundaries
- Starter surface placement in a real Shopify theme
- product page visual composition
- search experience
- FAQ generation and fallback
- comparison generation and fallback
- policy strip context
- contextual pill depth handoff
- Knowledge Sync healthy/unhealthy states
- analytics population
- App Store export package
- mobile and desktop layouts
- no debug/operator leakage

Release rule:

- do not ship Starter copy that is more mature than the verified product.

## 5) Build Order

### Step 1: Align Commercial Truth

Close:

- active tier names
- Free AI-search-only gate
- Starter allowed surfaces
- Starter sync/product/support posture
- old Growth/Pro cleanup

- every active product, billing, and copy surface tells the same tier story

### Step 2: Close Starter Surface Quality

- product insight quality
- AI search quality
- FAQ quality
- comparison quality
- policy strip quality
- contextual pill quality
- read-only depth handoff

Exit:

- Starter can be demonstrated from a real store without caveats about missing core surfaces

### Step 3: Finish Merchant Activation

- theme placement guidance

- launch packet generation

- unanswered/action-intent questions

Close:

- short demo clips

- App Review guide

## 6) Exit Gate

Phase 2 is complete when:

- Starter can be sold honestly as full read-only embedded store intelligence
- Free is AI search only across product, billing, docs, App Store, and partner catalog
- Starter surfaces are live, gated, and merchant-placeable
- merchant setup and Knowledge Sync states are understandable
- basic analytics show usage and value
- App Store copy and screenshots match the shipped product
- support docs and launch packets match the actual product
- no Elite action claims leak into Starter launch material

---

## 8) Risks

| Risk | Why It Matters | Mitigation |
|---|---|---|
| Starter is described before it is verified | Creates App Store and merchant trust risk | Tie copy to verified surfaces only |
| Free scope leaks into Starter value | Reduces paid conversion | Keep Free AI search only |
| Analytics become too technical | Merchant cannot see value | Use business language and surface-level summaries |
| Setup depends on operator knowledge | Solo developer cannot support every install manually | Build checklists, blockers, and launch packets |
| Elite claims leak into Starter launch | Overpromises support/actions | Keep order lookup and write actions out of Starter |
| Screenshots show the wrong product shape | Reinforces chatbot framing | Lead with embedded surfaces, not chat |

---

## 9) Handoff To Phase 3

Phase 3 Partner Enablement Foundation can start once Starter has:

- stable surface catalog
- clear entitlement truth
- repeatable setup checklist
- launch verification packet
- basic support runbook
- enough product clarity for an integrator to deploy it for a client

The partner catalog should mirror this Starter truth instead of inventing a separate partner-facing product.
